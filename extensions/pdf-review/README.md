# TeX PDF Review

PDF上で文章や図表にコメント・返信を付け、執筆側ではSyncTeXでTeX原稿へ移動するVS Code拡張です。Marketplaceへの公開、アカウント、外部サーバーは不要です。

## 導入

このテンプレートのDev Containerでは接続時に自動導入されます。初回のVSIX構築にはネットワークが必要です。完了後はPDFの右クリックから利用でき、既存のLaTeX Workshopも併用できます。既存コンテナで自動導入を反映するには `Dev Containers: Rebuild Container` を実行してください。
失敗時はコンテナ内で `node .devcontainer/install-pdf-review.cjs` を実行すると再試行できます。再接続時は変更や拡張の欠落がなければ導入を省略します。

コンテナを使わずレビューする人や、VSIXを手動で配布する場合は、以下の手順を使います。

VS Code **1.143.0以降**を使用します。ソースからパッケージを作る場合は、Node.js 22.13以降（推奨24系）で、このディレクトリ内から実行してください。

```sh
npm ci --ignore-scripts
npm run package
```

`dist/tex-template-pdf-review.vsix` ができます。VS Codeのコマンドパレットから **Extensions: Install from VSIX...** を実行して選択します。

執筆側がDev Containerを使っている場合は、**コンテナへ接続したウィンドウで**インストールしてください。レビューする側は通常のローカルVS Codeで利用でき、TeXとDockerは不要です。

## レビューする

1. エクスプローラー内のPDFを右クリックし、**PDFレビュー: PDF／レビューを開く**を選択します。コマンドパレットからも実行できます。
2. レビューの保存先（`.pdfreview`）を選択します。PDFと、その時点のコメントをこの1ファイルにまとめます。元のPDFは変更しません。
3. PDFの文章をドラッグで選択し、右クリックから **コメントを追加**。ツールバーのボタンでも追加できます。
4. 表示名と本文を入力し、**投稿**します。図表には **図表の範囲指定** を使って矩形をドラッグできます。
5. ハイライトや余白のマーカーをクリックすると、右側のコメント欄に対応するスレッドを表示します。
6. **返信／編集／削除／解決／再開** ができます。解決済みコメントはチェックボックスで表示を切り替えます。
7. 作成済みの `.pdfreview` を相手に渡します。相手もこの拡張で開けば、同じPDF・コメント・返信・解決状態を確認できます。

投稿等はその都度保存します。VS CodeのUndo/Redo等で未保存になった場合はCtrl+Sで保存してください。別名のコピーには **PDFレビュー: レビューを別名で保存** を使います。同名の既存レビューを新規作成操作で上書きしません。

自動保存に失敗した場合は、投稿をタブに反映したまま警告と未保存表示を出します。再投稿せずCtrl+Sで保存してください。未保存のタブを破棄すると、その変更は失われます。

未投稿の下書きはVS Code内にも保存し、同じ環境で同じレビューを開き直すと復元します。下書きは共有ファイルには含まれないため、相手に渡す前に投稿してください。
返信・編集先のコメントが削除された場合は、入力中の本文を同じPDF範囲の新規コメントの下書きとして残します。

`.pdfreview` がJSONのテキストとして表示された場合は、タブの **Reopen Editor With... → PDFレビュー** を選択するか、コマンドパレットの **PDFレビュー: PDF／レビューを開く** から開いてください。

コメント本文はテキストとして表示し、HTMLやスクリプトは実行しません。表示名は本人認証ではなく、利用者が入力する名前です。

## コメントからTeXへ移動する

執筆プロジェクトのフォルダーを開き、コメントの **TeXへ移動** を選択します。現在のテンプレートのDev Containerには必要な `synctex` が入っています。

- レビュー作成時、PDFの隣にある同名の `.synctex.gz` とワークスペース内の原稿の照合情報を取り込みます。
- PDFだけから作成されたレビューの場合は、初回の移動時に **同じ版のPDF** を選んで対応情報を取り込めます。隣の `.synctex.gz` と原稿が必要です。異なる版のPDFは拒否します。
- PDF座標をSyncTeXで原稿のファイル・行に変換し、エディターを横に開きます。マクロ・数式・図表では生成元の行や周辺に移動する場合があります。
- 原稿に行が追加されている場合、保存時点の行と周辺のハッシュを照合します。一意に対応しない場合は警告し、元の行番号付近を開くか利用者が選びます。
- ワークスペース外へ向くパスやシンボリックリンクは原稿への移動に使用しません。
- 相対パスに同名の原稿候補が複数ある場合は、誤移動を避けるため対応情報の取込を止めます。絶対パスのInputを記録する設定でPDFを再生成してください（この環境のLuaLaTeXでは通常その形式になります）。

**レビュー対象PDFとSyncTeX・原稿は同じビルドのものを用意してください。** 原稿のハッシュはレビュー作成・情報取込時点を記録するもので、ビルドの来歴そのものを証明するものではありません。

## PDFの版と受け渡し

`.pdfreview` 内には **作成時のPDFを保存** します。元のPDFが再ビルドされても、レビュー対象は変わらず、指摘箇所を見失いません。修正後のPDFをレビューするときは、新しい名前のレビューを作成してください。

この初版では、コメントを新しいPDFへ自動転記する機能、複数人が別々に編集したレビューの自動マージ、リアルタイム同期は提供しません。WordのコメントUIを参考にしていますが、Word文書の変更追跡と同じ仕組みではありません。

ファイルにはPDF全文、コメント、取り込んだ場合はSyncTeXと原稿の相対パス・照合用ハッシュが含まれます。TeX本文は格納しません。これらのデータを外部へ自動送信しません。**PDF単体や通常のPDFリーダーにはコメントは表示されません**。標準PDF注釈への書き出しは未対応です。

## 制限

- PDFは32 MiB、レビュー全体は64 MiBまでです。
- 1スレッドの範囲は1ページ内です。ページをまたぐ指摘はページごとに追加してください。
- テキストを持たない画像・スキャンのPDFは矩形で指定します。OCRは行いません。
- パスワード付きPDFは現在サポート対象外です。
- 別のPC・別のコンテナでも、同じプロジェクト内の相対パスを維持して原稿フォルダーを開いてください。
- 未信頼のワークスペースでは拡張を有効にしません。

## 開発と検証

```sh
npm run build
npm test
npx playwright install chromium
npm run test:ui
npm run test:vscode
```

`test:ui` はリポジトリのサンプルPDFで選択・右クリック・返信・倍率変更・解決／再開・再読込・矩形コメントを確認します。`test:vscode` はVS Code 1.143.1の実Extension Hostで起動、カスタムエディター、保存・再読込を確認します。インストール済みVS Codeを使う場合は `VSCODE_EXECUTABLE_PATH` に実行ファイルを指定できます。Linuxの画面なし環境では `xvfb-run -a npm run test:vscode` を使います。

Dev Container内では `npm run test:synctex` でLuaLaTeXによる実PDFとSyncTeXを生成し、保存したPDFからTeXへの対応、行追加後の追跡、元のPDFを上書きした後の独立性を検証します。生成物は専用一時ディレクトリで処理し、原稿を変更しません。

依存はlockfileで固定し、PDF.jsの表示資材はVSIX内へ同梱します。実行時のCDNアクセスはありません。`npm audit` で開発用依存も含めて検査できます。

# PDFレビュー拡張の実装・検証記録

2026-11-06、作業ブランチ `feat/pdf-review-comments`、バージョン0.1.1の初版。

## 実装

- `extensions/pdf-review` に独立した未公開VSIXとして実装。既存のLaTeX Workshopのビルド・ビューア設定は変更しない。
- PDF.jsを同梱し、PDFの文章選択・右クリック・複数行ハイライト・矩形指定と、右側のコメント欄を提供。
- 投稿、返信、編集、削除確認、解決／再開、解決済み表示の切替、表示名、保存と別名コピーに対応。未投稿の下書きは同じ環境のVS Code内で復元する。
- PDFとコメントを単一の `.pdfreview` に保存し、保存時点のPDFを維持。原稿を再ビルドしても別の文章を指さない。
- SyncTeX情報を保存し、TeXのファイル・行へ移動。原稿の行と周辺のハッシュで挿入後の位置を追跡し、曖昧な場合は利用者へ確認する。
- 絶対パスを持つSyncTeXのInput情報は、プロジェクト内の相対パスへ置換して保存する。TeX本文は保存しない。

## ローカルでの検証

- Windows、VS Code 1.143.1の実Extension Hostで拡張の起動・コマンド登録・カスタムエディター・文書保存・閉じる／再表示が成功。
- VSIXを通常プロファイルとは別の検証用プロファイルへインストール。実VS CodeのPDF上で日本語の範囲選択、右クリック、コメント入力・投稿、ファイルへの保存、閉じて再表示した際のハイライトとコメントの復元を確認。
- Playwright + 実PDF.js + サンプルの日本語PDFで、選択、右クリック、文字列としての安全な表示、返信・編集、下書き破棄の確認、倍率変更、解決／再開、再読込、矩形、複数行のコメントを検査。
- 単体テストで、保存形式の往復、操作の非破壊性、PDFハッシュの照合、不正な座標・パス・Base64の拒否、CRLFと行追加、曖昧な原稿位置の扱いを確認。
- Dev Container内のLuaLaTeXで実PDF・SyncTeXを生成し、保存したPDFから `main.tex:5` へ対応付けること、先頭に行を挿入すると6行目へ追跡すること、元のPDFを上書きしてもレビュー用PDFが維持されることを確認。
- 実Dev Containerの画面でも、コメントから5行目へ移動でき、保存済みの行追加後は6行目、さらにエディター内だけの未保存の行追加後は7行目へ追跡できた。対応付けと選択範囲は同じTextDocumentの内容を使い、原稿用のエディターグループを再利用する。
- 既存の22項目の機能テスト、ZIP相当ビルド、権限・パス制限の検査も成功。
- 追加依存はlockfileで固定。開発用ツールを含む `npm audit` は指摘0件。パッケージ作成も成功。

## 確認範囲と制限

Windows上の通常UIに加え、VS Code 1.145.1から実際のDev Containerへ接続し、コメントのボタンから検証原稿を開く一連の操作も確認した。
この接続時、永続ボリューム内の旧 `textlint.nodePath` が `/usr/local/lib/node_modules` のまま残っていたため、既存のdevcontainer.jsonが指定する `/opt/textlint/node_modules` へ揃えた。他のRemote Machine設定は保持した。
新しいCIジョブは追加したが、このブランチを未pushの間はGitHub Actions自体の実行結果はない。

初版では新しいPDFへのコメント自動転記、複数レビューのマージ、同時編集、通常のPDF注釈への書出しは対象外。
利用方法・サイズ上限・対応情報については [拡張のREADME](../extensions/pdf-review/README.md) を参照。
